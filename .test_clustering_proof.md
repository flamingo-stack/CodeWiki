# test_clustering_proof.py

An integration/manual proof test script that validates the LLM-based module clustering pipeline correctly groups semantically related code components into distinct modules. It exercises `cluster_modules` against a synthetic set of 20 components organized into four clear semantic groups (Auth, User, API, Data) and reports whether the clustering output honors the expected `<GROUPED_COMPONENTS>` tag format.

## Key Components

- **Environment setup** — loads `.env.local` via `dotenv`, configures logging, and resolves `TEST_REPO_PATH` (falling back to the script's directory) for use as the fake repository root.
- **`Config` instantiation** — builds a `codewiki.src.config.Config` object wiring together cluster/main/fallback models (`gpt-4o`, `gpt-4o`, `claude-opus-4-5-20251101`) and their respective API keys and base URLs, plus token limits (`max_token_per_module=50`, `cluster_max_tokens=4096`).
- **Synthetic `Node` components** — generates 20 `Node` instances (from `codewiki.src.be.dependency_analyzer.models.core`) split into four groups by naming/path convention: `AuthController0-4`, `UserService5-9`, `ApiController10-14`, `DataRepository15-19`.
- **`cluster_modules` invocation** — calls the clustering entry point with the leaf node IDs, component map, config, and empty starting module tree to produce a `module_tree` result.
- **Result validation & reporting** — inspects the size of the returned `module_tree` and prints pass/fail/partial outcomes, exiting with status codes (`0` for success or acceptable partial result, `1` for outright failure).

## Usage Example

Run directly as a script after configuring API credentials:

```bash
export OPENAI_API_KEY="sk-..."
export ANTHROPIC_API_KEY="sk-ant-..."
python test_clustering_proof.py
```

Optionally override the fake repo path or use separate keys per model tier:

```bash
export TEST_REPO_PATH=/path/to/some/repo
export CLUSTER_API_KEY="sk-..."
export MAIN_API_KEY="sk-..."
export FALLBACK_API_KEY="sk-ant-..."
python test_clustering_proof.py
```

**Expected outcomes:**
- Exit `1`: empty `module_tree` — clustering failed to follow the expected output format.
- Exit `0` (warning): exactly 1 module returned — format followed but result too coarse.
- Exit `0` (success): multiple modules returned — clustering correctly split components into semantic groups, printed with component counts and sample members.
