Proof-of-concept integration test that validates the `cluster_modules` function correctly groups semantically related components into distinct modules using an LLM backend.

## Key Components

| Component | Description |
|---|---|
| `cluster_modules` | Core function under test — clusters leaf nodes into a module tree |
| `Node` | Data model representing a single code component (class, file, etc.) |
| `Config` | Configuration object wiring model selection, API keys, and output paths |
| `components` dict | 20 synthetic `Node` objects organized into 4 semantic groups |
| `module_tree` | Output validated for correct grouping count and structure |

## Usage Example

```bash
# Set required API keys, then run directly
export OPENAI_API_KEY=sk-...
export ANTHROPIC_API_KEY=sk-ant-...

python test_clustering_proof.py
```

Expected exit outcomes:

```text
Exit 0 → ✅ SUCCESS  — 2+ modules returned (fix proven)
Exit 0 → ⚠️  WARNING — 1 module returned (LLM parsed tags but collapsed groups)
Exit 1 → ❌ FAILED   — empty module tree (LLM did not follow <GROUPED_COMPONENTS> format)
```

## Test Structure

The script constructs 20 Java class stubs split across four clearly named semantic groups:

```text
Auth  (0–4)   → AuthController0 … AuthController4
User  (5–9)   → UserService5    … UserService9
API   (10–14) → ApiController10 … ApiController14
Data  (15–19) → DataRepository15 … DataRepository19
```

A successful run requires the LLM to emit the `<GROUPED_COMPONENTS>` tag format and return **at least two** distinct modules, proving the clustering pipeline parses and routes LLM output correctly.
