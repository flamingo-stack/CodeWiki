A diagnostic test script that validates the `cluster_modules` function with verbose logging enabled, using sample Java components to verify LLM-powered module clustering behavior.

## Key Components

| Component | Description |
|---|---|
| `cluster_modules` | Core function under test — groups leaf nodes into logical modules |
| `Config` | Configuration object wiring model credentials, paths, and API endpoints |
| `Node` | Represents a single code component (class, function, etc.) fed into the clusterer |
| `components` dict | Four sample Java classes (`AuthController`, `AuthService`, `UserController`, `UserService`) simulating a real dependency graph |
| `module_tree` | Output dict — maps module names to their grouped component lists |

## Usage Example

```bash
# Set environment variables first
export OPENAI_API_KEY="sk-..."
export ANTHROPIC_API_KEY="sk-ant-..."

# Run the test with live log output
python test_with_logging.py
```

## Environment Variables

| Variable | Default | Purpose |
|---|---|---|
| `MAIN_MODEL` | `gpt-4o` | Primary doc generation model |
| `CLUSTER_MODEL` | `gpt-4o` | Module clustering model |
| `FALLBACK_MODEL` | `claude-opus-4-5-20251101` | Fallback if primary fails |
| `OPENAI_API_KEY` | — | OpenAI credentials |
| `ANTHROPIC_API_KEY` | — | Anthropic credentials |

## Notes

- Reads credentials from `.env.local` via `python-dotenv`
- Output artifacts written to `/tmp/codewiki_test/`
- A result of `len(module_tree) == 0` signals an LLM parsing failure — check `[INFO]` logs for the raw response
