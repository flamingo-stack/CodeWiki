# test_with_logging.py

A standalone manual test script for exercising the `cluster_modules` clustering pipeline against a real repository, with full logging enabled to inspect LLM interactions during module tree generation.

## Key Components

- **Path/environment setup** — inserts the script's directory into `sys.path` and loads environment variables from `.env.local` via `python-dotenv`.
- **`setup_logging()`** — initializes logging configuration (from `codewiki.src.be.dependency_analyzer.utils.logging_config`) before any clustering logic runs, so LLM request/response logs are captured.
- **`Config`** — builds a configuration object (`codewiki.src.config.Config`) specifying repo path, output directories, max depth, and model/API settings for the "cluster", "main", and "fallback" model tiers, sourced from environment variables with sensible defaults (e.g. `gpt-4o`, OpenAI/Anthropic endpoints).
- **Sample `Node` components** — hardcodes four fake Java class nodes (`AuthController`, `AuthService`, `UserController`, `UserService`) to serve as leaf nodes for clustering.
- **`cluster_modules(...)`** — the core function under test, invoked with the sample components and config to produce a `module_tree`.

## Usage Example

Run the script by providing a repository path either as a CLI argument or via environment variable:

```bash
# Via environment variable
export TEST_REPO_PATH=/path/to/some/repo
export OPENAI_API_KEY=sk-...
python test_with_logging.py

# Or via positional argument
python test_with_logging.py /path/to/some/repo
```

Optional environment variables to override model/provider settings:

```bash
export MAIN_MODEL=gpt-4o
export CLUSTER_MODEL=gpt-4o
export FALLBACK_MODEL=claude-opus-4-5-20251101
export CLUSTER_API_KEY=...
export MAIN_API_KEY=...
export FALLBACK_API_KEY=...
```

Expected output on success:

```text
🤖 Using model: gpt-4o

🔄 Clustering...

================================================================================
✅ SUCCESS: 2 modules created
   - auth: 2 components
   - user: 2 components
```

If the LLM fails to produce a valid clustering, the script prints `❌ FAILED: Empty module tree` and directs you to check the INFO-level logs printed above for the raw LLM response — useful for debugging prompt/response issues in `cluster_modules`.
