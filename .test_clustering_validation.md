Validates the clustering validation logic used in `cluster_modules.py`, specifically testing the `json.loads()` parsing and component ID validation that ensures LLM responses contain valid integer-based component references.

## Key Components

### `simulate_validation(response_content, max_id)`
Replicates the validation logic from `cluster_modules.py` (lines 338–369). Parses a JSON string and enforces:
- Valid JSON structure (must be a `dict`)
- All component IDs are bare integers (not strings or class names)
- All IDs fall within the valid range `0` to `max_id`

### `run_tests()`
Iterates over 10 predefined test cases covering valid and invalid input scenarios, compares actual outcomes against expected results, and prints a pass/fail summary.

### `test_cases`
A list of 10 scenario dicts covering:

| Scenario | Expected |
|---|---|
| Bare integers | ✅ Pass |
| Quoted integers (`"0"`, `"1"`) | ❌ Fail |
| String class names | ❌ Fail |
| Mixed types | ❌ Fail |
| Out-of-range ID | ❌ Fail |
| Negative ID | ❌ Fail |
| Multiple valid modules | ✅ Pass |
| Malformed JSON (trailing comma) | ❌ Fail |
| Empty components list | ✅ Pass |
| Missing components key | ✅ Pass |

## Usage Example

```python
# Run all tests from the command line
python test_clustering_validation.py

# Or call simulate_validation directly in a REPL
from test_clustering_validation import simulate_validation

success, tree = simulate_validation(
    '{"auth": {"components": [0, 1, 2]}}',
    max_id=10
)
print(success)  # True
print(tree)     # {'auth': {'components': [0, 1, 2]}}

# Catch invalid string IDs
success, tree = simulate_validation(
    '{"auth": {"components": ["AuthService"]}}',
    max_id=10
)
print(success)  # False
print(tree)     # None
```
