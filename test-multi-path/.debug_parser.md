Diagnostic script that verifies the `DependencyParser` can locate and parse Python source files across single and multi-path repository configurations.

## Key Components

| Element | Description |
|---|---|
| `parser_single` | `DependencyParser` instance scanning only the `main/` subdirectory |
| `parser_multi` | `DependencyParser` instance scanning both `main/` and `deps/` subdirectories |
| `components_single` / `components_multi` | Parsed component dictionaries printed for quick inspection |

## Usage Example

```bash
# Run from the repository root
python debug_parser.py
```

Expected output:

```text
Main path: /path/to/tests/main
Deps path: /path/to/tests/deps
Main exists: True
Deps exists: True

Files in main:
  - example.py

Files in deps:
  - helper.py

======================================================================
Testing single path parser...
======================================================================

Single path found 3 components
  - example.MyClass: class

======================================================================
Testing multi-path parser...
======================================================================

Multi-path found 7 components
  - helper.util_fn: function
```

## Notes

- Prepends `CODEWIKI_ROOT` to `sys.path` so `codewiki` is importable without installation.
- Globs only `*.py` files when listing directory contents — non-Python files are ignored.
- Prints at most **5** components for the single-path run and **10** for the multi-path run to keep output readable.
- Useful when adding new test fixtures under `main/` or `deps/` to confirm the parser picks them up before running the full test suite.
