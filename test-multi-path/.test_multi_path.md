Comprehensive test suite that validates CodeWiki's multi-path source analysis feature, covering backward compatibility, component namespacing, cross-path dependency detection, and error handling.

## Key Components

### Helper Functions
- `create_test_config()` — Builds a `Config` instance for test scenarios with optional `additional_source_paths`
- `print_header()`, `print_success()`, `print_error()`, `print_warning()`, `print_info()` — ANSI-colored console output utilities using the `Colors` class

### Test Functions
- `test_single_path()` — Verifies backward compatibility: analyzes `test/main/` and asserts `service.py` and `controller.py` are discovered
- `test_multiple_paths()` — Analyzes three directories simultaneously (`main/`, `deps/`, `external/`) and asserts all expected components are found per path
- `test_component_namespacing()` — Confirms that component IDs are globally unique across paths and warns when path namespace is absent from an ID
- `test_cross_path_dependencies()` — Detects edges in the dependency graph where `source` and `target` belong to different root paths (e.g., `main/service.py → deps/helper.py`)

## Usage Example

```python
# Run all tests directly
python tests/test_multi_path.py

# Or call individual test functions programmatically
from tests.test_multi_path import test_single_path, test_multiple_paths

passed = test_single_path()
print("Single path OK:", passed)

passed = test_multiple_paths()
print("Multi path OK:", passed)
```

Expected directory layout for the tests to pass:

```text
tests/
├── test_multi_path.py
├── main/
│   ├── service.py      # imports from deps/helper.py
│   └── controller.py
├── deps/
│   ├── helper.py
│   └── utils.py
└── external/
    └── plugin.py
```

> Each test function returns `True` on success or `False` on failure, and cleans up its temporary output directory via `shutil.rmtree` in a `finally` block regardless of outcome.
