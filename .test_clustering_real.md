Integration test script that validates the `cluster_modules` function triggers an actual LLM call by creating enough synthetic components to exceed the token threshold, then verifies the clustering output is non-empty.

## Key Components

| Component | Description |
|---|---|
| `cluster_modules` | Core function under test — groups leaf nodes into a module tree via LLM |
| `Node` | Dependency graph node representing a single source file component |
| `Config` | Runtime configuration wiring models, API keys, and token limits |
| `max_token_per_module` | Set to `5000` (lowered) to force the LLM clustering path |

## Usage Example

```bash
# Set required environment variables, then run directly
export OPENAI_API_KEY=sk-...
export CLUSTER_MODEL=gpt-4o

python test_clustering_real.py
```

```python
# Core test pattern — create 20 synthetic Java class nodes
components = {}
for i in range(20):
    components[str(i)] = Node(
        id=str(i), name=f"Component{i}", component_type="class",
        file_path=f"{test_repo}/test/Component{i}.java",
        relative_path=f"test/Component{i}.java", language="java"
    )

module_tree = cluster_modules(
    leaf_nodes=list(components.keys()),
    components=components,
    config=config,
    current_module_tree={},
    current_module_name=None,
    current_module_path=[]
)

# Exits 0 on success, 1 if module_tree is empty
```

## Notes

- Requires a `.env.local` file with `OPENAI_API_KEY` (and optionally `ANTHROPIC_API_KEY` for fallback)
- `test_repo` path is hardcoded to a local machine path — update before running in a different environment
- Models and API keys are all overridable via environment variables (`MAIN_MODEL`, `CLUSTER_MODEL`, `FALLBACK_MODEL`, etc.)
- See source: [`test_clustering_real.py`](https://github.com/flamingo-stack/CodeWiki/blob/main/test_clustering_real.py)
