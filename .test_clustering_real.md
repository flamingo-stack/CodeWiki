This script is a manual integration test that verifies real LLM-driven module clustering by forcing `cluster_modules` to invoke an actual LLM call, rather than relying on mocks. It creates enough synthetic components to exceed a deliberately lowered token threshold, ensuring the clustering logic must split them into multiple modules using a live model API.

## Key Components

- **Config setup**: Builds a `Config` object from environment variables (loaded via `.env.local`), specifying main/cluster/fallback models, API keys, and base URLs for OpenAI and Anthropic.
- **`max_token_per_module=5000`**: Intentionally lowered to force the clustering algorithm to trigger, since 20 components would otherwise fit in a single module.
- **Synthetic components**: Generates 20 `Node` instances (`Component0`...`Component19`) of type `"class"` with fake Java file paths, simulating a real dependency graph's leaf nodes.
- **`cluster_modules(...)`**: The core function under test, imported from `codewiki.src.be.cluster_modules`, called with the synthetic components and config to produce a `module_tree`.
- **Result validation**: Checks that `module_tree` is non-empty (clustering succeeded), prints module names and their component counts, and exits with status 0 (success) or 1 (failure).

## Usage Example

Run directly as a script after setting required environment variables:

```bash
# Required environment variables (in .env.local or shell)
export OPENAI_API_KEY="sk-..."
export ANTHROPIC_API_KEY="sk-ant-..."
export TEST_REPO_PATH="/path/to/test/repo"   # optional, defaults to script dir
export MAIN_MODEL="gpt-4o"                    # optional
export CLUSTER_MODEL="gpt-4o"                 # optional

python test_clustering_real.py
```

Expected output on success:

```text
🤖 Model: gpt-4o
📏 Max tokens per module: 5000

📦 Components: 20

🔄 Running clustering...

================================================================================
✅ SUCCESS: 3 modules
   - ModuleA: 7 components
   - ModuleB: 6 components
   - ModuleC: 7 components
```

This test is intended for local/manual verification of clustering behavior against live LLM endpoints—not for CI, since it consumes real API quota and depends on external network access.
