A simple integration smoke-test that validates the `cluster_modules` function correctly groups code components and that the underlying LLM respects the expected `<GROUPED_COMPONENTS>` output format.

## Key Components

| Name | Type | Description |
|------|------|-------------|
| `config` | `Config` | Full CodeWiki configuration object built from environment variables, pointing at a local test repository |
| `components` | `dict[str, Node]` | Four hardcoded Java `Node` objects (`AuthController`, `AuthService`, `UserController`, `UserService`) used as clustering input |
| `cluster_modules(...)` | Function call | Core function under test; expected to return a non-empty `module_tree` dict |

## Usage Example

```bash
# Set required environment variables (or use .env.local)
export OPENAI_API_KEY="sk-..."
export ANTHROPIC_API_KEY="sk-ant-..."

# Run the test directly
python test_clustering_simple.py
```

```python
# Expected exit behaviour
# Exit 0 → clustering succeeded, module_tree is non-empty
# Exit 1 → LLM did not return <GROUPED_COMPONENTS> tags; clustering failed
```

## Pass / Fail Criteria

- **✅ Pass (`exit 0`)** — `cluster_modules` returns at least one module; each module is printed with its component count.
- **❌ Fail (`exit 1`)** — `module_tree` is empty, indicating the LLM ignored the required tag format.

## Notes

- Model selection (`MAIN_MODEL`, `CLUSTER_MODEL`, `FALLBACK_MODEL`) and API keys are all sourced from the environment, making it easy to swap providers without code changes.
- The test repository path is hardcoded to a local macOS path and must be updated for other environments.
- See the source at [`test_clustering_simple.py`](https://github.com/flamingo-stack/CodeWiki/blob/main/test_clustering_simple.py) and related module at [`codewiki/src/be/cluster_modules`](https://github.com/flamingo-stack/CodeWiki/blob/main/codewiki/src/be/cluster_modules).
