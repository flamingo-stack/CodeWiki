# test_clustering_simple.py

A standalone smoke-test script that verifies the `cluster_modules` function correctly parses LLM output according to the expected `<GROUPED_COMPONENTS>` tag format. It exercises the clustering pipeline end-to-end with a small, hardcoded set of Java class components to confirm the LLM produces a valid, non-empty module tree.

## Key Components

- **Config setup** — Builds a `Config` object using environment variables (loaded via `.env.local`) for model names, API keys, and base URLs, with sensible fallbacks (e.g., `gpt-4o`, `claude-opus-4-5-20251101`).
- **Test components** — Defines 4 sample `Node` instances (`AuthController`, `AuthService`, `UserController`, `UserService`) representing Java classes to be clustered.
- **`cluster_modules` invocation** — Calls the clustering function from `codewiki.src.be.cluster_modules` with the test components and an empty initial module tree.
- **Pass/fail reporting** — Prints diagnostic output and exits with status code `1` if the resulting module tree is empty (indicating the LLM failed to follow the expected format), or `0` on success with a summary of created modules.

## Usage Example

Run directly from the command line after setting up environment variables in `.env.local`:

```bash
# Required/optional env vars: TEST_REPO_PATH, MAIN_MODEL, CLUSTER_MODEL,
# OPENAI_API_KEY, ANTHROPIC_API_KEY, etc.
python test_clustering_simple.py
```

Expected output on success:

```text
🤖 Using model: gpt-4o
   API key: SET

📦 Test components: 4
   [0] AuthController
   [1] AuthService
   [2] UserController
   [3] UserService

🔄 Running clustering...
================================================================================
================================================================================

✅ SUCCESS: 2 modules created
   - auth: 2 components
   - user: 2 components
```

This script is intended as a quick manual/CI check rather than a full `pytest` test suite—it exits with a non-zero code on failure, making it suitable for use in shell scripts or CI pipelines to validate LLM prompt compliance before running the full clustering pipeline on a real repository.
