Brief description: A forced integration test that validates LLM-based module clustering by setting an artificially low token threshold (`max_token_per_module=50`) to guarantee the LLM clustering call is triggered, then asserts the response conforms to the expected `<GROUPED_COMPONENTS>` tag format.

## Key Components

| Element | Description |
|---|---|
| `config` | `Config` instance with `max_token_per_module=50` to force LLM invocation |
| `components` | 10 synthetic `Node` objects simulating Java class components |
| `cluster_modules(...)` | Core function under test — groups leaf nodes into a module tree via LLM |
| Exit codes | `sys.exit(1)` on empty result (LLM format failure), `sys.exit(0)` on success |

## Usage Example

```bash
# Set required env vars in .env.local, then run directly:
MAIN_MODEL=gpt-4o \
CLUSTER_API_KEY=sk-... \
python test_clustering_forced.py
```

```python
# Core pattern being tested — low threshold forces LLM path
config = Config(
    max_token_per_module=50,   # Forces LLM call (normal values are much higher)
    cluster_max_tokens=4096,
    cluster_model="gpt-4o",
    ...
)

module_tree = cluster_modules(
    leaf_nodes=list(components.keys()),
    components=components,
    config=config,
    current_module_tree={},
    current_module_name=None,
    current_module_path=[]
)

# Test passes only if LLM returns non-empty module tree
assert len(module_tree) > 0, "LLM did not follow <GROUPED_COMPONENTS> format"
```

## Notes

- Requires `.env.local` with `OPENAI_API_KEY` (and optionally `ANTHROPIC_API_KEY` for fallback)
- Validates the **response parsing path**, not just that the LLM was called — an empty `module_tree` indicates a format/parsing failure
