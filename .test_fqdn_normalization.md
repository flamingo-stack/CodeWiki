Test suite validating FQDN (Fully Qualified Domain Name) normalization logic used to resolve LLM-generated component identifiers against actual graph node keys, covering prefix stripping, fuzzy matching, collision detection, and scoring strategies.

## Key Components

| Test Function | Description |
|---|---|
| `test_strip_deps_prefix` | Verifies `deps.` prefix is correctly stripped before lookup |
| `test_fuzzy_component_name_match` | Matches by last segment when full path is wrong |
| `test_path_suffix_matching` | Matches by trailing N-segment suffix across different base paths |
| `test_exact_fqdn_match` | Confirms exact FQDN keys resolve without modification |
| `test_short_id_mapping` | Validates `short_id → FQDN` reverse mapping construction |
| `test_partial_path_mapping` | Builds and validates partial-path maps (2–4 trailing segments) |
| `test_collision_detection` | Detects when the same `short_id` maps to multiple FQDNs |
| `test_best_path_match_scoring` | Scores candidates by shared segment count; verifies top result |
| `test_non_existent_component` | Confirms hallucinated/unknown components produce no matches |
| `test_double_class_name` | Handles paths where the class name appears twice (e.g., `Foo.Foo`) |
| `test_java_package_path` | Resolves full Java package paths (`com.openframe.management...`) |

## Usage Example

```bash
# Run the full suite with verbose output
python -m pytest test_fqdn_normalization.py -v

# Run a single test
python -m pytest test_fqdn_normalization.py::test_fuzzy_component_name_match -v
```

## Notes

- Tests use a lightweight `Node = namedtuple('Node', ['short_id'])` mock — no external graph dependency required.
- Collision detection relies on `collections.defaultdict` to track `short_id` conflicts.
