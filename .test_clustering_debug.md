Standalone debug script for inspecting LLM responses during the `cluster_modules` pipeline. It monkey-patches the LLM client to capture raw model output, then runs a small synthetic clustering job against a hardcoded Java test repo to verify parsing and grouping behaviour.

## Key Components

| Symbol | Type | Description |
|---|---|---|
| `capture_llm_response()` | Function | Monkey-patches `create_llm_client` to intercept and store the raw LLM response string in `captured_response` |
| `captured_response` | Global | Holds the raw LLM string after the clustering call completes |
| `components` | Dict | Four synthetic `Node` objects (Auth/User Controllers and Services) used as leaf nodes for the test |
| `Config` | Instance | Wires model names and API keys from environment variables with OpenAI defaults |

## Usage Example

```bash
# Set required environment variables (or add to .env.local)
export OPENAI_API_KEY="sk-..."
export MAIN_MODEL="gpt-4o"
export CLUSTER_MODEL="gpt-4o"

# Run from the repo root
python test_clustering_debug.py
```

```python
# The script surfaces two outcomes:

# ❌ FAILED — module tree is empty; also reports whether
#    <GROUPED_COMPONENTS> XML tag was present in the LLM response,
#    helping diagnose prompt/parsing mismatches.

# ✅ SUCCESS — prints the full module_tree as JSON so you can
#    verify cluster names and membership without touching the
#    production pipeline.
```
