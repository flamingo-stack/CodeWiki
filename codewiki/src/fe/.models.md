Defines the core data models for the CodeWiki web application, covering repository submission validation, job lifecycle tracking, and documentation cache management.

## Key Components

| Class | Type | Purpose |
|---|---|---|
| `RepositorySubmission` | Pydantic `BaseModel` | Validates incoming repository URL submissions via HTTP |
| `JobStatusResponse` | Pydantic `BaseModel` | Serializes job status data for API responses |
| `JobStatus` | `@dataclass` | Internal runtime representation of a documentation generation job |
| `CacheEntry` | `@dataclass` | Tracks cached documentation results with access metadata |

### `JobStatus` — Status Values

The `status` field follows this lifecycle:

```text
queued → processing → completed
                    ↘ failed
```

## Usage Example

```python
from datetime import datetime
from models import RepositorySubmission, JobStatus, CacheEntry, JobStatusResponse

# Validate an incoming repo URL (raises ValidationError if invalid)
submission = RepositorySubmission(repo_url="https://github.com/flamingo-stack/CodeWiki")

# Create an internal job tracker
job = JobStatus(
    job_id="abc-123",
    repo_url=str(submission.repo_url),
    status="queued",
    created_at=datetime.utcnow()
)

# Serialize for API response
response = JobStatusResponse(
    job_id=job.job_id,
    repo_url=job.repo_url,
    status=job.status,
    created_at=job.created_at,
    progress="Cloning repository..."
)

# Store a completed result in cache
cache_entry = CacheEntry(
    repo_url=job.repo_url,
    repo_url_hash="sha256_hash_here",
    docs_path="/docs/abc-123/",
    created_at=datetime.utcnow(),
    last_accessed=datetime.utcnow()
)
```

> **Note:** `RepositorySubmission` and `JobStatusResponse` use Pydantic for automatic validation and JSON serialization. `JobStatus` and `CacheEntry` are plain dataclasses used internally within the application runtime.
