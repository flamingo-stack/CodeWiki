Manages asynchronous documentation generation jobs using a thread-based queue system, handling job lifecycle from repository cloning through documentation generation to result caching.

## Key Components

- **`BackgroundWorker`** — Core class that orchestrates job processing with an internal `Queue` and persistent job state
  - `start()` / `stop()` — Controls the daemon worker thread lifecycle
  - `add_job(job_id, job)` — Enqueues a `JobStatus` job for processing
  - `get_job_status(job_id)` / `get_all_jobs()` — Job state retrieval
  - `load_job_statuses()` — Restores completed jobs from `jobs.json` on startup
  - `save_job_statuses()` — Persists job state to disk after each transition
  - `_reconstruct_jobs_from_cache()` — Backward-compatible fallback that rebuilds job history from `CacheManager` entries when `jobs.json` is absent
  - `_worker_loop()` — Polling loop (1s sleep) that dequeues and dispatches jobs
  - `_process_job(job_id)` — Full job execution: cache check → clone → config → async doc generation → cache write → cleanup

## Usage Example

```python
from codewiki.src.be.background_worker import BackgroundWorker
from codewiki.src.be.cache_manager import CacheManager
from codewiki.src.be.models import JobStatus
from datetime import datetime

cache_manager = CacheManager()
worker = BackgroundWorker(cache_manager, temp_dir="/tmp/codewiki")
worker.start()

job = JobStatus(
    job_id="flamingo-stack--CodeWiki",
    repo_url="https://github.com/flamingo-stack/CodeWiki",
    status="queued",
    created_at=datetime.now(),
)
worker.add_job(job.job_id, job)

# Poll for completion
import time
while True:
    status = worker.get_job_status(job.job_id)
    print(f"Status: {status.status} — {status.progress}")
    if status.status in ("completed", "failed"):
        break
    time.sleep(2)
```

> **Note:** Each job runs its async `DocumentationGenerator` in an isolated `asyncio` event loop via `loop.run_until_complete()`, keeping the worker thread safe from loop conflicts. Temporary clone directories are unconditionally removed in the `finally` block regardless of job outcome.
