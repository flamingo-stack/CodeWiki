# config.py

Centralized configuration settings for the CodeWiki web application, defining directory paths, cache/queue/job parameters, server defaults, and Git cloning behavior via a single settings class.

## Key Components

- **`WebAppConfig`** — Configuration class holding class-level constants and utility methods:
  - **Directory settings**: `CACHE_DIR`, `TEMP_DIR`, `OUTPUT_DIR` — relative paths for output artifacts, cached data, and temporary files.
  - **Queue settings**: `QUEUE_SIZE` — maximum size for the job processing queue.
  - **Cache settings**: `CACHE_EXPIRY_DAYS` — number of days before cached entries expire.
  - **Job cleanup settings**: `JOB_CLEANUP_HOURS`, `RETRY_COOLDOWN_MINUTES` — control stale job cleanup and retry timing.
  - **Server settings**: `DEFAULT_HOST`, `DEFAULT_PORT` — default bind address and port for the web server.
  - **Git settings**: `CLONE_TIMEOUT`, `CLONE_DEPTH` — timeout (seconds) and shallow-clone depth for repository cloning operations.
  - **`ensure_directories()`** — class method that creates `CACHE_DIR`, `TEMP_DIR`, and `OUTPUT_DIR` (including parent directories) if they don't already exist.
  - **`get_absolute_path(path)`** — class method converting a relative path string to its absolute filesystem path.

## Usage Example

```python
from config import WebAppConfig

# Ensure required directories exist at startup
WebAppConfig.ensure_directories()

# Access configuration values
print(f"Server will run on {WebAppConfig.DEFAULT_HOST}:{WebAppConfig.DEFAULT_PORT}")
print(f"Cache expires after {WebAppConfig.CACHE_EXPIRY_DAYS} days")

# Resolve a relative path to an absolute one
abs_cache_path = WebAppConfig.get_absolute_path(WebAppConfig.CACHE_DIR)
print(f"Cache directory (absolute): {abs_cache_path}")

# Use timeout/depth settings when cloning a repo
clone_timeout = WebAppConfig.CLONE_TIMEOUT
clone_depth = WebAppConfig.CLONE_DEPTH
```

This class acts as a single source of truth for application-wide settings, avoiding scattered magic numbers/paths throughout the codebase. All settings are accessed as class attributes without needing to instantiate `WebAppConfig`.
