Orchestrates the clustering of code components (leaf nodes) into logical modules using an LLM, with ID-based component mapping to minimize token usage and fuzzy-matching complexity.

## Key Components

| Function | Description |
|---|---|
| `extract_module_hint(fqdn)` | Extracts a short, human-readable module name from a fully qualified domain name (FQDN) |
| `extract_package_hint(fqdn)` | Extracts a package/category hint (e.g., `controller`, `service`) from an FQDN |
| `create_component_id_map(components)` | Builds bidirectional integer ID ↔ FQDN mappings to reduce LLM prompt size |
| `format_potential_core_components(...)` | Formats leaf nodes into ID-based strings (with and without source code) for LLM consumption |
| `normalize_component_ids_by_lookup(...)` | Replaces integer IDs in the LLM response with their corresponding FQDNs |
| `cluster_modules(...)` | Main entry point — validates, formats, and sends components to the LLM for module clustering |

## Usage Example

```python
from codewiki.src.be.dependency_analyzer.cluster_modules import cluster_modules
from codewiki.src.config import Config

# Cluster leaf nodes into logical modules
module_tree = cluster_modules(
    leaf_nodes=["main-repo.src/services/auth.py::AuthService"],
    components=components_dict,   # Dict[str, Node]
    config=Config(),
    current_module_name="auth",
    current_module_path=["services"]
)

# Result: {"AuthModule": {"components": ["main-repo.src/services/auth.py::AuthService"]}}
```

## Notes

- **ID-based prompting**: Components are assigned integer IDs before LLM calls, keeping prompts compact. `normalize_component_ids_by_lookup` restores FQDNs from the response.
- **Pre-flight validation**: `validate_components_before_clustering` filters out leaf nodes absent from the components dictionary before any LLM call.
- **FQDN formats supported**: Both dot-separated (`com.openframe.api.Service`) and path-based (`main-repo.src/services/auth.py::AuthService`) FQDNs are handled.
