Handles the grouping of code components into logical modules using LLM-based clustering, with ID-based component mapping to avoid passing verbose FQDNs to the language model.

## Key Components

- **`extract_module_hint(fqdn)`** — Parses a fully qualified domain name (FQDN) to extract a human-readable module name (e.g., `openframe-api-service` → `api-service`).

- **`extract_package_hint(fqdn)`** — Extracts a package/category label from an FQDN by matching common patterns like `controller`, `service`, `repository`, etc.

- **`create_component_id_map(components)`** — Builds a bidirectional integer-ID ↔ FQDN mapping for all components, reducing token usage when sending data to the LLM.

- **`format_potential_core_components(leaf_nodes, components)`** — Groups leaf nodes by file, filters out invalid entries, and returns ID-based component listings (with and without source code) alongside the ID mapping dictionaries.

- **`normalize_component_ids_by_lookup(module_tree, id_to_fqdn)`** — Replaces integer IDs returned by the LLM back into their original FQDNs using direct lookup, handling out-of-range or non-integer IDs gracefully.

- **`cluster_modules(...)`** — Entry point that orchestrates the full clustering pipeline: validates leaf nodes, formats components with IDs, counts tokens, and prepares data for LLM prompt formatting via `format_cluster_prompt`.

## Usage Example

```python
from codewiki.src.be.dependency_analyzer.cluster_modules import cluster_modules
from codewiki.src.config import Config

result = cluster_modules(
    leaf_nodes=["main-repo.src/services/auth.py::AuthService"],
    components=components_dict,
    config=Config(),
    current_module_name="auth",
    current_module_path=["services"]
)

# result: {"auth": {"components": ["main-repo.src/services/auth.py::AuthService"]}}
```
