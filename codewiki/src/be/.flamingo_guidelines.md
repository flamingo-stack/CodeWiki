Loads and manages Flamingo markdown formatting guidelines, custom repository instructions, and validation rules from environment variables for injection into LLM prompts.

## Key Components

| Name | Type | Description |
|------|------|-------------|
| `load_flamingo_guidelines()` | function | Reads markdown guidelines from the file path in `FLAMINGO_MARKDOWN_GUIDELINES_PATH` env var |
| `load_custom_instructions()` | function | Reads and sanitizes repository-specific instructions from the `CUSTOM_REPO_INSTRUCTIONS` env var |
| `load_validation_rules()` | function | Reads markdown validation rules from the file path in `VALIDATION_RULES_PATH` env var |
| `sanitize_problematic_patterns()` | function | Normalizes GitHub Actions `${{...}}` syntax to prevent shell/prompt conflicts |
| `sanitize_and_escape_format_braces()` | function | Escapes `{curly braces}` for safe use with Python's `str.format()`, preserving numeric placeholders like `{0}` |
| `escape_format_braces()` | function | Deprecated wrapper; delegates to `sanitize_and_escape_format_braces()` |
| `get_guidelines_section()` | function | Returns a formatted, brace-escaped guidelines block ready for prompt injection |
| `get_validation_rules_section()` | function | Returns formatted validation rules block for prompt injection |
| `FLAMINGO_MARKDOWN_GUIDELINES` | module constant | Guidelines content loaded at import time |
| `CUSTOM_REPO_INSTRUCTIONS` | module constant | Sanitized custom instructions loaded at import time |
| `MARKDOWN_VALIDATION_RULES` | module constant | Validation rules content loaded at import time |

## Usage Example

```python
from codewiki.src.be.flamingo_guidelines import (
    get_guidelines_section,
    get_custom_instructions_section,
    get_validation_rules_section,
)

# Compose an LLM system prompt with all injected context
system_prompt = (
    get_custom_instructions_section()
    + get_guidelines_section()
    + get_validation_rules_section()
    + "Generate documentation for the following code...\n"
)

# Environment variables required at runtime:
# FLAMINGO_MARKDOWN_GUIDELINES_PATH=/tmp/flamingo-guidelines.md
# CUSTOM_REPO_INSTRUCTIONS="Follow Flamingo Stack conventions..."
# VALIDATION_RULES_PATH=/tmp/markdown-validation-rules.md
```

## Environment Variables

| Variable | Description |
|----------|-------------|
| `FLAMINGO_MARKDOWN_GUIDELINES_PATH` | Path to the Flamingo markdown guidelines file (downloaded by GitHub Actions) |
| `CUSTOM_REPO_INSTRUCTIONS` | Raw text of repository-specific instructions (not a file path) |
| `VALIDATION_RULES_PATH` | Path to the markdown validation rules file (downloaded by GitHub Actions) |

All three values are loaded eagerly at module import time. Missing variables produce warnings but do not raise exceptions — affected sections return empty strings and are silently omitted from prompts.
