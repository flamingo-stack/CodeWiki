# agent_orchestrator.py

Defines `AgentOrchestrator`, the core component that builds and runs `pydantic_ai` agents to generate documentation for repository modules. It selects agent configuration (tools, system prompt, retries) based on module complexity, wires up dependencies via `CodeWikiDeps`, and drives the per-module documentation pipeline—loading/saving the module tree, invoking the agent with usage limits, and persisting generated Markdown docs to disk with idempotency checks.

## Key Components

- **`AgentOrchestrator`** — Main orchestration class initialized with a `Config` object; holds fallback LLM models and optional custom prompt instructions.
- **`create_agent(module_name, components, core_component_ids)`** — Builds a `pydantic_ai.Agent` instance. Uses `is_complex_module()` to decide between:
  - **Complex agent**: tools = `read_code_components_tool`, `str_replace_editor_tool`, `generate_sub_module_documentation_tool`; system prompt via `format_system_prompt`.
  - **Leaf agent**: tools = `read_code_components_tool`, `str_replace_editor_tool`; system prompt via `format_leaf_system_prompt`.
  - Both configured with `retries=3` to avoid tool retry-limit failures.
- **`process_module(module_name, components, core_component_ids, module_path, working_dir)`** *(async)* — End-to-end processing for a single module:
  - Loads/creates the shared `module_tree.json` (always in the base docs directory, independent of nested `working_dir`).
  - Skips generation if overview or module `.md` file already exists (idempotent).
  - Formats the user prompt via `format_user_prompt` and runs the agent with `UsageLimits(request_limit=1000)`.
  - Saves the updated module tree and verifies the output file was written, logging diagnostics on failure.
  - Returns the updated module tree dict; re-raises exceptions after logging traceback.

## Usage Example

```python
from codewiki.src.config import Config
from codewiki.src.be.agent_orchestrator import AgentOrchestrator

config = Config(repo_path="/path/to/repo", docs_dir="/path/to/docs", max_depth=3)
orchestrator = AgentOrchestrator(config)

module_tree = await orchestrator.process_module(
    module_name="auth_service",
    components=components_dict,        # Dict[str, Node]
    core_component_ids=["Node1", "Node2"],
    module_path=["src", "services"],
    working_dir="/path/to/docs/services/auth_service",
)
```

## Notes

- Logfire instrumentation is currently disabled (commented out) in favor of standard `logging`.
- The `retries=3` and `usage_limits=UsageLimits(request_limit=1000)` settings are fork-specific patches (`FLAMINGO_PATCH`) addressing tool retry and request-limit exhaustion issues.
- `process_module` is safe to re-run: existing overview or module docs short-circuit regeneration.
