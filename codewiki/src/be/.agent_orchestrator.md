Orchestrates AI agent creation and execution for generating documentation across code modules, routing to either complex (multi-tool) or leaf (single-module) agents based on module complexity.

## Key Components

- **`AgentOrchestrator`** — Main class that manages agent lifecycle and documentation generation
  - `__init__(config)` — Initializes fallback LLM models and optional custom prompt instructions
  - `create_agent(module_name, components, core_component_ids)` — Selects and builds the appropriate `pydantic_ai.Agent` (complex vs. leaf) with configured tools and retry logic
  - `process_module(module_name, components, core_component_ids, module_path, working_dir)` — Async method that runs the agent against a module, skips already-documented modules, enforces usage limits, and persists the updated module tree

## Usage Example

```python
from codewiki.src.config import Config
from codewiki.src.be.agent_orchestrator import AgentOrchestrator

config = Config(
    repo_path="/path/to/repo",
    docs_dir="/path/to/docs",
    max_depth=3,
)

orchestrator = AgentOrchestrator(config)

result = await orchestrator.process_module(
    module_name="api_service_core",
    components=components_dict,
    core_component_ids=["ComponentA", "ComponentB"],
    module_path=["architecture", "api_service_core"],
    working_dir="/path/to/docs/architecture/api_service_core",
)
```

## Notes

- Complex modules receive three tools: `read_code_components`, `str_replace_editor`, and `generate_sub_module_documentation`; leaf modules receive only the first two
- Agent retries are set to `3` and request limit is capped at `1000` to prevent runaway LLM usage
- `module_tree.json` is always resolved from the **base** docs directory, regardless of the module's nesting depth
- Documentation generation is **idempotent** — existing `.md` files and `overview.md` are detected and skipped
