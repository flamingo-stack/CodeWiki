Orchestrates the documentation generation process for a repository by building dependency graphs, clustering modules, and generating LLM-powered documentation in a hierarchical directory structure.

## Key Components

### `DocumentationGenerator`
Main class that coordinates the full documentation pipeline.

| Method | Description |
|--------|-------------|
| `__init__(config, commit_id)` | Initializes with `Config`, `DependencyGraphBuilder`, and `AgentOrchestrator` |
| `_get_nested_working_dir(base_dir, module_path)` | Computes nested output directory path from module hierarchy |
| `create_documentation_metadata(working_dir, components, num_leaf_nodes)` | Writes a `metadata.json` file with generation stats and file list |
| `get_processing_order(module_tree, parent_path)` | Returns topological processing order (leaf modules first) via DFS |
| `is_leaf_module(module_info)` | Returns `True` if a module has no children |
| `build_overview_structure(module_tree, module_path, working_dir)` | Injects child documentation content into the module tree for overview prompts |
| `generate_module_documentation(components, leaf_nodes)` | Async entrypoint that drives the full module doc generation loop |

## Usage Example

```python
from codewiki.src.config import Config
from codewiki.src.be.documentation_generator import DocumentationGenerator

config = Config(
    repo_path="/path/to/repo",
    docs_dir="/path/to/output/docs",
    main_model="gpt-4o",
    max_depth=3,
)

generator = DocumentationGenerator(config, commit_id="abc123")

# Build processing order from a saved module tree
order = generator.get_processing_order(module_tree)

# Generate all module docs (async)
import asyncio
asyncio.run(generator.generate_module_documentation(components, leaf_nodes))
```

## Output Structure

```text
docs/
├── metadata.json
├── module_tree.json
├── first_module_tree.json
├── overview.md
└── ModuleName/
    └── ModuleName.md
        └── SubModule/
            └── SubModule.md
```

## Notes

- Processing order is **leaf-first** (bottom-up), so child documentation is available when generating parent overviews.
- Directory nesting mirrors the module hierarchy — each module gets its own subdirectory containing a `.md` file of the same name.
- Relies on [`AgentOrchestrator`](https://github.com/flamingo-stack/CodeWiki/blob/main/codewiki/src/be/agent_orchestrator.py) for LLM calls and [`DependencyGraphBuilder`](https://github.com/flamingo-stack/CodeWiki/blob/main/codewiki/src/be/dependency_analyzer.py) for graph construction.
