Provides path traversal and symlink protection for safe file reading within a restricted directory boundary.

## Key Components

- **`_inside(base, target)`** — Internal helper that checks whether `target` resolves to a path within `base`, compatible with Python 3.8 (fallback) and 3.9+ (`is_relative_to`).
- **`assert_safe_path(base_dir, target)`** — Raises `PermissionError` if `target` is a symlink or resolves outside `base_dir`.
- **`safe_open_text(base_dir, target, encoding)`** — Validates the path via `assert_safe_path`, then opens the file using a low-level file descriptor with `O_NOFOLLOW` (on supported platforms) to prevent TOCTOU symlink attacks.

## Usage Example

```python
from pathlib import Path
from security import safe_open_text, assert_safe_path

REPO_ROOT = Path("/srv/repo")

# Safe read within repo boundary
content = safe_open_text(REPO_ROOT, REPO_ROOT / "docs/readme.md")

# Raises PermissionError — path escapes repo
safe_open_text(REPO_ROOT, Path("/etc/passwd"))

# Raises PermissionError — symlink blocked
safe_open_text(REPO_ROOT, REPO_ROOT / "link_to_secret")

# Validate only, without reading
assert_safe_path(REPO_ROOT, REPO_ROOT / "src/main.py")
```

## Security Notes

| Threat | Mitigation |
|---|---|
| Path traversal (`../../etc/passwd`) | `_inside()` resolves the full path before comparison |
| Symlink escape | `target.is_symlink()` check + `O_NOFOLLOW` flag |
| TOCTOU race | Low-level `os.open()` with `O_NOFOLLOW` prevents symlink substitution after validation |
| Python 3.8 compatibility | Fallback string prefix check when `is_relative_to` is unavailable |
