# Call Graph Analyzer

Central orchestrator for multi-language call graph analysis. It coordinates language-specific analyzers (Python, JavaScript, TypeScript, Java, C#, C, C++, PHP) to build a comprehensive, unified call graph across a repository, extracting functions/nodes and their call relationships.

## Key Components

- **`CallGraphAnalyzer`** — Main orchestrator class that maintains state (`functions`, `call_relationships`) across the analysis run.
  - `analyze_code_files(code_files, base_dir)` — Entry point that analyzes all provided code files, resolves and deduplicates call relationships, and returns a structured result containing the call graph summary, function list, relationship list, and visualization data.
  - `extract_code_files(file_tree)` — Recursively traverses a nested file tree structure and filters files by supported extensions (via `CODE_EXTENSIONS`), returning a flat list of code file metadata (path, name, extension, language).
  - `_analyze_code_file(repo_dir, file_info)` — Reads file content safely and routes analysis to the correct language-specific handler based on detected language.
  - Language-specific handlers: `_analyze_python_file`, `_analyze_javascript_file`, `_analyze_typescript_file`, `_analyze_java_file`, `_analyze_csharp_file`, `_analyze_c_file`, `_analyze_cpp_file`, `_analyze_php_file` — each lazily imports the relevant tree-sitter/AST-based analyzer module, extracts functions and relationships, and merges them into the shared `functions` dict and `call_relationships` list.

## Usage Example

```python
from codewiki.src.be.dependency_analyzer.call_graph_analyzer import CallGraphAnalyzer

analyzer = CallGraphAnalyzer()

# Extract code files from a file tree structure
code_files = analyzer.extract_code_files(file_tree)

# Run full call graph analysis
result = analyzer.analyze_code_files(code_files, base_dir="/path/to/repo")

print(result["call_graph"]["total_functions"])
print(result["call_graph"]["total_calls"])
print(result["call_graph"]["languages_found"])

# Access extracted functions and relationships
functions = result["functions"]
relationships = result["relationships"]
```

**Notes:**
- Errors during per-file analysis are logged and do not halt the overall process, ensuring partial results are still returned.
- Functions are keyed by `func.id` (or a fallback `"{file_path}:{func.name}"`) to avoid duplicate entries.
- The class relies on `_resolve_call_relationships()`, `_deduplicate_relationships()`, and `_generate_visualization_data()` (defined elsewhere in the class) to finalize the graph before returning results.
