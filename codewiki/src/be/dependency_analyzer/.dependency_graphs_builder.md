Builds and validates a dependency graph from a code repository, returning parsed components and filtered leaf nodes suitable for documentation or analysis traversal.

## Key Components

### `DependencyGraphBuilder`

Main class responsible for orchestrating the full dependency analysis pipeline.

| Method | Description |
|---|---|
| `__init__(config: Config)` | Initializes the builder with a `Config` instance |
| `build_dependency_graph()` | Parses the repo, builds the graph, validates it, and returns `(components, leaf_nodes)` |

**Internal pipeline steps:**

1. Ensures output directories exist and computes sanitized graph file paths
2. Resolves include/exclude patterns and single vs. multi-path source roots
3. Parses all source files via `DependencyParser` into typed components
4. Saves the raw dependency graph as JSON
5. Builds a traversable graph via `build_graph_from_components`
6. Validates graph completeness with `validate_graph_completeness`
7. Extracts leaf nodes and filters them to valid types (`class`, `interface`, `struct`, or `function` for C-based codebases)

## Usage Example

```python
from codewiki.src.config import Config
from codewiki.src.be.dependency_analyzer.dependency_graphs_builder import DependencyGraphBuilder

config = Config(
    repo_path="/path/to/repo",
    dependency_graph_dir="/tmp/graphs"
)

builder = DependencyGraphBuilder(config)
components, leaf_nodes = builder.build_dependency_graph()

print(f"Total components: {len(components)}")
print(f"Leaf nodes to document: {len(leaf_nodes)}")

for node in leaf_nodes:
    comp = components[node]
    print(f"  - {node} ({comp.component_type})")
```

## Notes

- Leaf nodes are filtered to `class`, `interface`, and `struct` types by default; `function` is added automatically when no OOP types are detected (e.g., C codebases)
- Nodes containing error keywords (`error`, `exception`, `failed`, `invalid`) are skipped with a warning
- Multi-path mode is supported via `config.all_source_paths` for monorepos or projects spanning multiple directories
- The serialized graph JSON is written to `<dependency_graph_dir>/<repo_name>_dependency_graph.json`
