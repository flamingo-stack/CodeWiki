## Purpose

This module provides the `DependencyGraphBuilder` class, which orchestrates the end-to-end process of parsing a repository's source files, constructing a dependency graph, validating its completeness, and filtering leaf nodes down to those relevant for downstream documentation generation (e.g., classes, interfaces, structs, or functions for C-based codebases).

## Key Components

- **`DependencyGraphBuilder`** — Main class that drives dependency analysis.
  - `__init__(config: Config)` — Initializes the builder with a `Config` object containing repo paths, include/exclude patterns, and output directories.
  - `build_dependency_graph() -> tuple[Dict[str, Any], List[str]]` — Core method that:
    1. Ensures the output directory exists and computes sanitized file paths for saving results.
    2. Supports single-path or multi-path repository analysis via `Config.all_source_paths`.
    3. Uses `DependencyParser` to parse source files into components (respecting include/exclude patterns).
    4. Logs a breakdown of parsed component types.
    5. Saves the dependency graph to disk via `parser.save_dependency_graph`.
    6. Builds a traversal graph with `build_graph_from_components` and validates completeness via `validate_graph_completeness`.
    7. Computes leaf nodes with `get_leaf_nodes`, then filters them to keep only valid types (`class`, `interface`, `struct`, or `function` if no OOP types are found), discarding invalid/error-like identifiers or components missing from the parsed set.
    8. Returns a tuple of `(components, keep_leaf_nodes)`.

## Usage Example

```python
from codewiki.src.config import Config
from codewiki.src.be.dependency_analyzer.dependency_graphs_builder import DependencyGraphBuilder

# Load or construct a Config instance for the target repository
config = Config(
    repo_path="/path/to/repo",
    dependency_graph_dir="/path/to/output/graphs",
    include_patterns=["*.py"],
    exclude_patterns=["*/tests/*"],
)

builder = DependencyGraphBuilder(config)
components, leaf_nodes = builder.build_dependency_graph()

print(f"Parsed {len(components)} components")
print(f"Filtered to {len(leaf_nodes)} usable leaf nodes")
```

The returned `components` dict maps component identifiers to parsed component objects, and `leaf_nodes` is a filtered list of identifiers suitable for further processing (e.g., generating documentation per class/function).
