Tree-sitter-based static analyzer for C# source files that extracts structural nodes (classes, interfaces, structs, enums, records, delegates) and their call/inheritance relationships.

## Key Components

### `TreeSitterCSharpAnalyzer`
Main analyzer class that parses a C# file and populates two collections:
- `nodes` — list of `Node` objects representing top-level C# type declarations
- `call_relationships` — list of `CallRelationship` objects representing inheritance, property, field, and method parameter dependencies

**Key methods:**

| Method | Description |
|---|---|
| `_analyze()` | Initializes tree-sitter parser and drives extraction |
| `_extract_nodes()` | Recursively walks the AST to identify type declarations |
| `_extract_relationships()` | Recursively walks the AST to extract inter-type dependencies |
| `_find_containing_class()` | Traverses parent nodes to determine the enclosing type |
| `_is_primitive_type()` | Filters out C# built-in types from relationship tracking |
| `_get_module_path()` | Converts file path to dot-notation module identifier |
| `_get_identifier_name_cs()` | Extracts the identifier following a type keyword |

### `analyze_csharp_file` (module-level function)
Convenience wrapper that instantiates `TreeSitterCSharpAnalyzer` and returns the extracted nodes and relationships as a tuple.

## Usage Example

```python
from codewiki.src.be.dependency_analyzer.languages.csharp import analyze_csharp_file

file_path = "/repo/src/Services/UserService.cs"
content = open(file_path).read()

nodes, relationships = analyze_csharp_file(
    file_path=file_path,
    content=content,
    repo_path="/repo"
)

for node in nodes:
    print(f"{node.component_type}: {node.name} [{node.start_line}-{node.end_line}]")

for rel in relationships:
    print(f"{rel.caller} → {rel.callee} (line {rel.call_line})")
```

**Detected node types:** `class`, `abstract class`, `static class`, `interface`, `struct`, `enum`, `record`, `delegate`

**Detected relationship types:** inheritance (`base_list`), property types, field types, method parameter types — primitive and common BCL types are excluded automatically.
