# python.py

AST-based dependency analyzer for Python source files. It parses Python code using the built-in `ast` module to extract top-level classes and functions along with their call relationships, producing component IDs in `module.path::ClassName` FQDN format for consistency with the broader dependency graph and clustering system.

## Key Components

- **`PythonASTAnalyzer`** — An `ast.NodeVisitor` subclass that walks a Python file's AST and collects:
  - `visit_ClassDef` — Extracts class definitions (name, base classes, docstring, source range) and records inheritance relationships as `CallRelationship` entries.
  - `visit_FunctionDef` / `visit_AsyncFunctionDef` — Extracts top-level function definitions (skipping methods nested in classes as standalone nodes) via `_process_function_node`.
  - `visit_Call` — Detects function/method calls made from within top-level classes or functions and records them as `CallRelationship` objects, resolving calls to known local components when possible.
  - `_get_component_id` / `_get_module_path` / `_get_relative_path` — Helpers to build fully-qualified, dot-separated module paths from file paths, used to construct consistent component IDs.
  - `_get_call_name` — Resolves the callable name from a call expression (`ast.Name` or `ast.Attribute`), filtering out common Python built-ins (`print`, `len`, `isinstance`, etc.) to avoid noise.
  - `_should_include_function` — Filters out functions such as those prefixed with `_test_`.
  - `analyze()` — Entry point that parses `self.content` into an AST (suppressing `SyntaxWarning`s) and triggers traversal, logging results or errors.

- **`analyze_python_file(file_path, content, repo_path=None)`** — Module-level convenience function that instantiates `PythonASTAnalyzer`, runs `analyze()`, and returns a tuple of `(nodes, call_relationships)`.

## Usage Example

```python
from codewiki.src.be.dependency_analyzer.language_analyzers.python import analyze_python_file

with open("myproject/utils.py") as f:
    content = f.read()

nodes, relationships = analyze_python_file(
    file_path="myproject/utils.py",
    content=content,
    repo_path="myproject"
)

for node in nodes:
    print(node.component_type, node.id)

for rel in relationships:
    print(f"{rel.caller} -> {rel.callee} (resolved={rel.is_resolved})")
```

This returns `Node` objects (classes/functions) and `CallRelationship` objects (calls, inheritance) suitable for feeding into a dependency graph builder or clustering pipeline.
