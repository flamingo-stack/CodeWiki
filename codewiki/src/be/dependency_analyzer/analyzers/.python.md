Parses Python source files using the `ast` module to extract top-level classes and functions, along with their call relationships, for use in dependency graph analysis.

## Key Components

### `PythonASTAnalyzer` (class)
An `ast.NodeVisitor` subclass that walks a Python file's AST and collects structural information.

| Method | Description |
|---|---|
| `visit_ClassDef` | Extracts class nodes including base class inheritance relationships |
| `visit_FunctionDef` / `visit_AsyncFunctionDef` | Extracts top-level function nodes (skips class methods) |
| `visit_Call` | Records caller/callee relationships between top-level nodes |
| `_get_call_name` | Resolves call targets; filters out Python built-ins |
| `_get_component_id` | Generates dot-separated IDs (e.g., `my.module.MyClass.method`) |
| `analyze` | Entry point — parses content and runs the visitor |

### `analyze_python_file` (function)
Public API that instantiates `PythonASTAnalyzer`, runs analysis, and returns results.

## Usage Example

```python
from codewiki.src.be.dependency_analyzer.languages.python import analyze_python_file

source = """
class Foo:
    def bar(self): pass

def standalone(): pass
"""

nodes, relationships = analyze_python_file(
    file_path="myproject/module.py",
    content=source,
    repo_path="myproject"
)

for node in nodes:
    print(node.id, node.component_type)
# module.Foo  class
# module.standalone  function

for rel in relationships:
    print(rel.caller, "->", rel.callee)
```

## Notes

- Only **top-level** classes and functions are added as `Node` objects; class methods are traversed for call relationships but not individually indexed.
- Functions prefixed with `_test_` are excluded via `_should_include_function`.
- `SyntaxWarning` is suppressed during parsing to handle files with legacy escape sequences in strings.
- Call relationships to Python built-ins (`print`, `len`, `isinstance`, etc.) are silently filtered out.
