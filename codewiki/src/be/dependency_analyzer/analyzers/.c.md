# c.py

Tree-sitter based analyzer for C source files. Parses C code to extract call-graph nodes (functions, structs, global variables) and their call/usage relationships, feeding results into the broader multi-language dependency analysis pipeline.

## Key Components

- **`TreeSitterCAnalyzer`** — Main analyzer class that parses a C file's content using `tree_sitter_c` grammar and builds `Node` and `CallRelationship` objects.
  - `__init__(file_path, content, repo_path=None)` — Initializes and triggers analysis immediately.
  - `_analyze()` — Parses the source into an AST and orchestrates node/relationship extraction.
  - `_extract_nodes(node, top_level_nodes, lines)` — Recursively walks the AST to detect `function_definition`, `struct_specifier`, `type_definition` (typedef struct), and global variable `declaration` nodes, building `Node` objects.
  - `_extract_relationships(node, top_level_nodes)` — Recursively detects `call_expression` (function calls) and `identifier` usages of global variables, producing `CallRelationship` objects.
  - `_is_global_variable(node)` — Determines whether a declaration is at global (non-function) scope.
  - `_find_containing_function(node, top_level_nodes)` — Walks up the AST to find the enclosing function for a given node.
  - `_is_system_function(func_name)` — Filters out well-known C/SDL library calls (`printf`, `malloc`, `SDL_Init`, etc.) from call relationships.
  - `_get_module_path()`, `_get_relative_path()`, `_get_component_id(name)` — Helpers to compute module-qualified identifiers relative to `repo_path`.

- **`analyze_c_file(file_path, content, repo_path=None) -> Tuple[List[Node], List[CallRelationship]]`** — Module-level convenience function that instantiates `TreeSitterCAnalyzer` and returns its extracted nodes and relationships.

## Usage Example

```python
from codewiki.src.be.dependency_analyzer.languages.c import analyze_c_file

c_source = """
int counter = 0;

int increment() {
    counter++;
    return counter;
}

int main() {
    return increment();
}
"""

nodes, relationships = analyze_c_file(
    file_path="src/counter.c",
    content=c_source,
    repo_path="/repo/root"
)

for node in nodes:
    print(node.component_type, node.name, node.id)

for rel in relationships:
    print(rel.caller, "->", rel.callee, f"(line {rel.call_line})")
```

Unresolved cross-file callees (`is_resolved=False`) are expected to be resolved later by a downstream `CallGraphAnalyzer`, while same-file variable usages are marked `is_resolved=True`.
