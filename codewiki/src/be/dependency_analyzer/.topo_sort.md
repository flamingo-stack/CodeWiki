Topological sorting utilities for dependency graphs, providing cycle detection, cycle resolution, and multiple graph traversal strategies for ordering code components by their dependencies.

## Key Components

| Function | Description |
|---|---|
| `detect_cycles(graph)` | Implements Tarjan's algorithm to find strongly connected components (cycles) in a dependency graph |
| `resolve_cycles(graph)` | Breaks detected cycles by removing the first edge found in each SCC, returning an acyclic copy of the graph |
| `topological_sort(graph)` | Kahn's algorithm (BFS-based) topological sort; resolves cycles first, returns dependencies-first ordering |
| `dependency_first_dfs(graph)` | DFS traversal starting from root nodes (no incoming edges), ensuring dependencies appear before dependents |
| `build_graph_from_components(components)` | Converts a dict of code components with `depends_on` attributes into an adjacency-set graph |
| `get_leaf_nodes(graph, components)` | Identifies leaf nodes (nothing depends on them) and filters by component type (`class`, `interface`, `struct`, or `function` for C-based codebases) |

## Graph Convention

All functions use the **natural dependency direction**: an edge `A → B` means *A depends on B*. Root nodes have no outgoing edges; leaf nodes have no incoming edges.

## Usage Example

```python
from codewiki.src.be.dependency_analyzer.topo_sort import (
    build_graph_from_components,
    topological_sort,
    dependency_first_dfs,
    get_leaf_nodes,
)

# Build graph from parsed components
graph = build_graph_from_components(components)

# Get a linear build order (dependencies first)
order = topological_sort(graph)
print(order)  # ['utils', 'models', 'services', 'api']

# DFS-based alternative traversal
dfs_order = dependency_first_dfs(graph)

# Find entry-point components (leaf nodes)
leaves = get_leaf_nodes(graph, components)
```

## Notes

- Cycle breaking is **arbitrary** (first edge in each SCC removed); no semantic heuristic is applied.
- `get_leaf_nodes` automatically falls back to including `function` nodes when no `class`/`interface`/`struct` components exist (C-based codebases).
- All traversals are **deterministic** — sorted node iteration is used wherever result order matters.
