## ast_parser.py

This module implements Stage 2 of the dependency analysis pipeline: parsing the repository into Abstract Syntax Tree (AST)-derived structural and call-graph representations, then building a namespaced, fully-qualified dependency graph of code components (functions, classes, etc.) suitable for downstream clustering, summarization, and documentation generation.

## Key Components

- **`DependencyParser`**: Main class orchestrating repository parsing. Only the repository itself is parsed; code it imports from other repositories is looked up by the writing agents through the hub's code-graph tools.
  - `parse_repository(filtered_folders=None)`: Analyzes structure and call graph for the repository and builds its components.
  - `_get_namespace_from_path(repo_path)`: Derives a namespace string from the repository's directory name.
  - `_build_components_from_analysis(call_graph_result)`: Constructs `Node` objects keyed by fully-qualified domain name (FQDN) in `namespace.original_id` format, tracking `short_id` and `namespace` metadata.

- **`Node`** (imported from `codewiki.src.be.dependency_analyzer.models.core`): Data model representing a single code component (function, class, etc.) with metadata such as source location, docstring, parameters, and FQDN identifiers.

- **`AnalysisService`** (imported from `codewiki.src.be.dependency_analyzer.analysis.analysis_service`): Underlying service providing `_analyze_structure` (file discovery) and `_analyze_call_graph` (function/class extraction and relationship detection).

## Usage Example

```python
from codewiki.src.be.dependency_analyzer.ast_parser import DependencyParser

parser = DependencyParser(
    repo_path="/path/to/repo",
    include_patterns=["*.py", "*.cs"],
    exclude_patterns=["*Tests*"]
)
components = parser.parse_repository()

# Inspect resulting components
for fqdn, node in components.items():
    print(fqdn, node.component_type, node.namespace)
```
