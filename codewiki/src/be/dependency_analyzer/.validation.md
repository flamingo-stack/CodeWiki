Provides pre-flight and post-build validation utilities for dependency graph integrity, catching missing components and broken edges before or after graph construction.

## Key Components

| Function | Description |
|---|---|
| `validate_components_before_clustering` | Pre-flight check that all proposed leaf nodes reference existing components before clustering begins |
| `validate_graph_completeness` | Post-build check that verifies all graph nodes and dependency edges resolve to known components |
| `validate_determinism` | Generates a SHA-256 hash of the sorted graph structure to verify reproducibility across runs |

## Usage Example

```python
from validation import (
    validate_components_before_clustering,
    validate_graph_completeness,
    validate_determinism,
)

components = {
    "auth.py": {...},
    "db.py": {...},
    "api.py": {...},
}

graph = {
    "api.py": {"auth.py", "db.py"},
    "auth.py": set(),
    "db.py": set(),
}

leaf_nodes = ["auth.py", "db.py"]

# Pre-flight: confirm leaf nodes exist before clustering
validate_components_before_clustering(components, leaf_nodes)

# Post-build: confirm graph edges resolve to real components
validate_graph_completeness(components, graph)

# Determinism: hash the graph to compare runs
hash_val = validate_determinism(components, graph)
print(f"Graph hash: {hash_val}")
```

## Notes

- Both `validate_components_before_clustering` and `validate_graph_completeness` respect the `CODEWIKI_STRICT_MODE` environment variable — set it to `true` to raise a `ValueError` on failure instead of logging a warning and returning `False`.
- Error output is capped at 10–20 entries per check to keep logs readable for large graphs.
- `validate_determinism` produces no side effects and is safe to call at any point for auditing reproducibility.
