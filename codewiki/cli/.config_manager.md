Manages CodeWiki configuration by persisting non-sensitive settings to `~/.codewiki/config.json` and storing API keys securely in the system keychain via the `keyring` library.

## Key Components

- **`ConfigManager`** — Main class coordinating load/save of configuration and keyring access
- **`load()`** — Reads `config.json` and retrieves API keys from the system keychain
- **`save(**kwargs)`** — Persists model settings, URLs, token limits, and temperatures to JSON; writes API keys to keyring
- **`get_cluster_api_key()`** — Lazy-loads the cluster provider API key from keyring
- **Constants** — `CONFIG_DIR`, `CONFIG_FILE`, `CONFIG_VERSION`, and `KEYRING_SERVICE` define storage locations and the keyring namespace

## Usage Example

```python
from codewiki.cli.utils.config_manager import ConfigManager

manager = ConfigManager()

# Save initial configuration
manager.save(
    cluster_api_key="sk-cluster-...",
    main_api_key="sk-main-...",
    main_model="gpt-4o",
    cluster_model="gpt-4o-mini",
    fallback_model="gpt-3.5-turbo",
    default_output="docs",
    main_max_tokens=4096,
    cluster_max_tokens=2048,
)

# Load existing configuration
config_exists = manager.load()
if config_exists:
    cluster_key = manager.get_cluster_api_key()
```

## Storage Layout

| Data | Location |
|---|---|
| API keys | System keychain (`codewiki` service) |
| Model names, URLs, token limits | `~/.codewiki/config.json` |

## Notes

- Keyring availability is probed at init time; `KeyringError` exceptions are silently swallowed during reads but raised as `ConfigurationError` on writes
- `save()` performs partial updates — only explicitly provided arguments overwrite existing values
- Config version (`1.0`) is written to JSON for future migration support
