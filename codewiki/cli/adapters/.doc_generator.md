Async CLI adapter that wraps the backend `DocumentationGenerator`, adding progress tracking, verbose logging, and multi-provider LLM configuration for terminal-based documentation generation.

## Key Components

- **`CLIDocumentationGenerator`** — Main class that bridges the CLI and backend `DocumentationGenerator`
  - `__init__` — Initializes repo path, output dir, LLM config, optional diagrams dir, and a 5-stage `ProgressTracker`
  - `_configure_backend_logging` — Routes backend logs to stdout (verbose) or stderr warnings-only (quiet), using `ColoredFormatter`
  - `generate` — Synchronous entry point: builds `BackendConfig`, runs async generation, optionally generates HTML, finalizes the job
  - `_run_backend_generation` — Async method that drives the backend pipeline with per-stage progress reporting (truncated in this file)

## Usage Example

```python
from pathlib import Path
from codewiki.cli.doc_generator import CLIDocumentationGenerator

generator = CLIDocumentationGenerator(
    repo_path=Path("/path/to/repo"),
    output_dir=Path("/path/to/output"),
    config={
        "main_model": "gpt-4o",
        "cluster_model": "gpt-4o-mini",
        "main_api_key": "sk-...",
        "cluster_api_key": "sk-...",
        "main_base_url": "https://api.openai.com/v1",
        "max_depth": 2,
    },
    verbose=True,
    generate_html=True,
)

job = generator.generate()
print(f"Job status: {job.status}")
print(f"Output: {job.output_directory}")
```

## Notes

- Third-party library logs (`httpx`, `openai`, `anthropic`) are suppressed at module level to reduce noise.
- Additional source paths passed via `config['additional_paths']` are resolved relative to `repo_path` before being forwarded to `BackendConfig`.
- The `set_cli_context(True)` call signals the backend to adapt its behavior for CLI execution.
