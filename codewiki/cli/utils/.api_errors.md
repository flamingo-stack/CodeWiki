Provides LLM API error handling utilities that classify exceptions into actionable error messages and support fail-fast behavior for documentation generation workflows.

## Key Components

- **`APIErrorHandler`** — Static handler class that processes LLM API exceptions
  - `handle_api_error(error, context, fail_fast)` — Converts raw exceptions into `APIError` instances with user-friendly troubleshooting guidance; detects rate limits (429), auth failures (401), timeouts, and network errors
  - `display_api_error(error, module_name)` — Formats and prints API errors to the terminal using `click` with colored output

- **`wrap_api_call(func, *args, **kwargs)`** — Convenience wrapper that executes a callable, catches any exception, and either raises an `APIError` (fail-fast mode) or displays the error and returns `None`

## Usage Example

```python
from codewiki.cli.utils.api_errors import APIErrorHandler, wrap_api_call

# Direct error handling
try:
    response = llm_client.generate(prompt)
except Exception as e:
    api_error = APIErrorHandler.handle_api_error(e, context="auth_module")
    APIErrorHandler.display_api_error(api_error, module_name="auth_module")
    raise api_error

# Wrap a callable (fail-fast — raises APIError on failure)
result = wrap_api_call(
    llm_client.generate,
    prompt,
    fail_fast=True,
    context="readme_generator"
)

# Wrap a callable (soft failure — logs and returns None)
result = wrap_api_call(
    llm_client.generate,
    prompt,
    fail_fast=False,
    context="optional_module"
)
if result is None:
    # handle graceful degradation
    pass
```

## Error Classification

| Condition | Error Type |
|---|---|
| `429` / `rate limit` | Rate limit exceeded |
| `401` / `authentication` | Invalid or expired API key |
| `timeout` | Request timed out |
| `network` / `connection` | Connectivity failure |
| Any other | Generic LLM API error |
