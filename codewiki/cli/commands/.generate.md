## generate.py

Implements the `codewiki generate` CLI command, which orchestrates the end-to-end documentation generation workflow for a code repository: validating configuration and repository state, optionally creating a git branch, and invoking the LLM-powered documentation generator with user-specified options.

## Key Components

- **`parse_patterns(patterns_str)`** — Utility that splits a comma-separated string (e.g., file include/exclude patterns) into a cleaned list of strings.
- **`generate_command`** — The main `click.command` handler (registered as `generate`). Accepts numerous CLI options controlling output paths, caching, filtering, documentation type, custom instructions, token limits, and git branch/GitHub Pages behavior. It performs a staged workflow:
  1. **Configuration validation** — Loads and validates config via `ConfigManager`, populating API keys from the secure keyring.
  2. **Repository validation** — Resolves the current working directory, validates it as a supported repository via `validate_repository`, and detects git status.
  3. **Output directory checks** — Ensures the output path is writable and prompts (unless `--force`) before overwriting existing docs.
  4. **Git branch creation** (optional) — Uses `GitManager` to verify a clean working tree and create a new documentation branch.
  5. **Documentation generation** — Builds `GenerationOptions` and `AgentInstructions` (from `--include`, `--exclude`, `--focus`, `--doc-type`, `--instructions`) and invokes `CLIDocumentationGenerator`.

Errors are raised as `ConfigurationError`, `RepositoryError`, or `APIError` and handled uniformly via `handle_error`. Progress and debug output is managed through a custom `logger` created by `create_logger`.

## Usage Example

```bash
# Basic generation with defaults (./docs output)
codewiki generate

# Create a git branch and generate GitHub Pages index
codewiki generate --create-branch --github-pages

# Restrict scope and force full regeneration
codewiki generate --include "*.cs" --exclude "*Tests*" --no-cache

# Focus on specific modules with custom instructions and token overrides
codewiki generate --focus "src/core,src/api" \
    --doc-type architecture \
    --instructions "Focus on public APIs" \
    --max-tokens 16384
```

Programmatic invocation (e.g., in tests) typically goes through Click's test runner rather than calling `generate_command` directly, since it relies on `click.pass_context` and CLI-parsed options.
