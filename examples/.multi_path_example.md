Demonstrates multi-path repository analysis using `DependencyParser` and `RepoAnalyzer`, showing how to analyze multiple source directories simultaneously with namespace-aware component tracking.

## Key Components

| Function | Description |
|---|---|
| `example_single_path()` | Backward-compatible single-path parsing with include/exclude patterns |
| `example_multiple_paths()` | Multi-repo parsing with automatic namespace grouping and cross-namespace dependency detection |
| `example_repo_analyzer_multi_path()` | High-level `RepoAnalyzer` usage across multiple repos, returning summary and file tree |
| `example_component_details()` | Accessing per-namespace component metadata (type, file path, line range, dependencies) |
| `example_saving_output()` | Persisting the full multi-path dependency graph to a JSON file |

## Usage Example

```python
from codewiki.src.be.dependency_analyzer.ast_parser import DependencyParser

# Multi-path analysis with namespacing
parser = DependencyParser(
    ["/path/to/frontend", "/path/to/backend", "/path/to/shared"],
    include_patterns=["*.py", "*.ts", "*.tsx"],
    exclude_patterns=["*test*", "*spec*", "node_modules/*"]
)

components = parser.parse_repository()

# Components are prefixed by namespace (derived from directory name)
for comp_id, component in components.items():
    namespace = comp_id.split('.')[0]  # e.g., "frontend", "backend"
    print(f"{namespace}: {comp_id} -> {component.name}")

# Save the full graph to disk
parser.save_dependency_graph("/tmp/multi_path_analysis.json")
```

## Notes

- All example functions use **placeholder paths** — replace `/path/to/...` with real directories before running.
- Component IDs are automatically **namespaced** by directory name (e.g., `frontend.src.components.Button`) to avoid collisions across repos.
- Cross-namespace dependencies are preserved and visible in the parsed output.
