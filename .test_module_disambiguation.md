Validates the module-context disambiguation fix for CodeWiki's `_find_best_path_match()` function, demonstrating how module name context resolves ambiguous component path matches (e.g., multiple `DeviceController` or `SecurityConfig` classes across different service modules).

## Key Components

| Function | Description |
|---|---|
| `_find_best_path_match_original()` | Baseline scorer without module context — fails on equally-scored ambiguous candidates, returning `None` |
| `_find_best_path_match_enhanced()` | Enhanced scorer that accepts an optional `module_name` argument; applies exact-match (+3.0×segment) and partial-match (+1.5/segment) boosts plus a path-length penalty to break ties |
| `test_device_controller_disambiguation()` | Verifies the production bug scenario: `DeviceController` in `openframe-api-service` vs `openframe-external-api-service` |
| `test_external_api_disambiguation()` | Inverts the scenario, confirming the external variant wins when the module context changes |
| `test_security_config_disambiguation()` | Covers a three-candidate case (`SecurityConfig` across gateway, api, and auth services) |
| `main()` | Runs all three tests and reports a pass/fail summary with exit code |

## Usage Example

```python
# Run the full test suite from the repo root
python test_module_disambiguation.py

# Or call helpers directly in a REPL
from test_module_disambiguation import _find_best_path_match_enhanced

candidates = [
    "deps.openframe-oss-lib.openframe-api-service-core...DeviceController",
    "deps.openframe-oss-lib.openframe-external-api-service-core...DeviceController",
]

result = _find_best_path_match_enhanced(
    llm_id="DeviceController",
    candidates=candidates,
    module_name="openframe-api-service",  # context drives the winner
)
print(result)
# → "deps.openframe-oss-lib.openframe-api-service-core...DeviceController"
```

Expected output on success:

```text
✅ Passed: 3/3
🎉 All tests passed! Module disambiguation is working correctly.
```

## Notes

- The scoring algorithm splits `module_name` on `-` and `_`, lowercases each token, then looks for consecutive window matches inside the candidate path before falling back to individual segment counting.
- Set `logging.DEBUG` (already the default in this file) to see per-candidate score breakdowns.
